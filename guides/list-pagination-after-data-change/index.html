삭제·필터 뒤 목록이 꼬일 때 확인하는 순서

삭제나 필터로 결과 수가 바뀌면 전체 페이지 수를 새 전체 건수와 페이지당 표시 개수로 다시 계산한다. 현재 페이지 번호가 새 범위 안에 있는지 확인하고, 화면에 보이는 행은 그 페이지의 새 조회 결과로 바뀌었는지 본다. 페이지 번호 목록과 이전·다음 버튼은 새 전체 페이지 수와 현재 페이지 번호에 맞게 표시되는지 확인한다.

2026년 9월 3일Guides

삭제나 필터 뒤 목록이 비거나 지운 행이 다시 보인다면 데이터만 다시 불러오지 말고 페이지 상태도 함께 본다. 결과 수가 줄면 현재 페이지가 사라질 수 있다. 화면에는 이전 결과가 남아 있을 수도 있다.

확인 순서볼 것
1. 전체 건수삭제·필터 뒤 전체 결과 수가 실제 값으로 바뀌었는가
2. 전체 페이지 수새 전체 건수와 페이지당 표시 개수를 기준으로 다시 계산됐는가
3. 현재 페이지현재 페이지 번호가 새 전체 페이지 수 안에 있는가
4. 보이는 행현재 페이지에 보여야 할 새 행이 빠짐없이 보이는가
5. 페이지 이동이전·다음 버튼과 페이지 번호 목록이 새 페이지 수와 현재 페이지 번호에 맞게 표시되는가
6. 재진입새로고침하거나 다시 들어와도 같은 결과가 보이는가

마지막 행을 지우는 경우를 따로 시험한다

여러 행이 남아 있는 페이지에서 항목 하나를 지우는 테스트만으로는 페이지 경계 문제가 잘 드러나지 않는다. 한 페이지에 항목 하나만 남긴 뒤 그 항목을 지워 페이지 자체가 사라지는 상황도 시험한다.

필터도 같은 방식으로 본다. 높은 페이지에 있는 상태에서 검색·필터 결과를 크게 줄여 현재 페이지를 유효 범위 밖으로 만든다. 그때 화면이 새 범위 안의 페이지로 이동하는지 확인한다.

전체 건수와 화면의 행은 같은 조회 결과를 가리켜야 한다

전체 건수는 새 값인데 화면의 행은 이전 값이면 빈 페이지나 오래된 행이 생길 수 있다. 목록을 다시 불러올 때 전체 건수와 전체 페이지 수를 먼저 갱신한다. 현재 페이지 번호가 유효 범위를 벗어나면 새 범위 안의 페이지로 옮긴다. 화면에 보이는 행은 그 페이지의 새 조회 결과로 바꾸고, 이동 버튼과 페이지 번호 목록은 새 페이지 수와 현재 페이지 번호에 맞춰 표시한다.
