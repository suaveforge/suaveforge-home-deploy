외부 연동이 같은 이벤트를 두 번 보내도 결과는 한 번만 반영돼야 한다

결제사나 배송사 같은 외부 서비스는 응답을 받지 못하면 같은 이벤트를 다시 보낼 수 있다. 재전송을 새 요청으로 처리하면 주문 상태가 두 번 바뀌거나 알림이 중복 발송될 수 있다.

외부 서비스가 결제 완료나 배송 완료 같은 상태 변경을 우리 서버에 알려 주는 경우가 많다. 네트워크가 끊기거나 응답이 늦으면 상대 시스템은 같은 이벤트를 다시 보낼 수 있다.

외부 서비스가 이벤트 전송
   ↓
이벤트 식별값 확인
   ↓
처음 받은 이벤트인가?
   예 → 처리 후 식별값 저장
   아니오 → 다시 처리하지 않음

같은 내용을 두 번 받았다고 해서 두 번째 요청까지 다시 처리하면 문제가 생긴다. 주문 상태 변경 알림이 두 번 나가거나 포인트가 중복 지급될 수 있다.

단순히 요청이 들어온 시각이나 본문 내용만 비교하는 방식도 불안하다. 같은 내용의 정상 이벤트가 따로 생길 수 있기 때문이다. 외부 서비스가 제공하는 고유한 이벤트 식별값이 있다면 그 값을 기준으로 이미 처리했는지 확인하는 편이 안전하다.

검수할 때는 정상 요청 한 번만 보내지 말고 같은 이벤트를 연속으로 두 번 보내 본다. 두 번째 요청이 들어와도 사용자에게 보이는 결과와 데이터 변경은 한 번만 생겨야 한다.

외부 연동의 재시도는 흔한 상황이다. 같은 이벤트를 다시 받아도 이미 끝난 작업이 반복되지 않게 만들어야 한다.
