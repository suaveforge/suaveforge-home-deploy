성공 메시지가 떠도 결과가 바뀌지 않으면 실패다

저장, 업로드, 계정 수정, 로그 다운로드처럼 서로 다른 작업에서도 성공 표시는 떴지만 실제 데이터나 파일은 바뀌지 않은 사례가 반복된다. 완료 여부는 메시지가 아니라 작업 뒤의 상태로 확인해야 한다.

2026년 9월 2일Insights

버튼을 누른 뒤 “저장되었습니다”가 떴다고 해서 작업이 끝난 것은 아니다. 바꾼 값이 실제로 저장됐는지, 파일이 새 버전으로 바뀌었는지, 다음 화면이 새 상태를 보여주는지까지 확인해야 한다.

공개 버그 사례를 보면 성공 메시지가 나온 뒤에도 상품 값이 그대로이거나, CMS 내용이 저장되지 않거나, 계정 정보가 데이터베이스에 반영되지 않거나, 최신 로그 파일이 내려오지 않은 일이 있었다. 실제 프로젝트에서도 저장 성공 뒤 화면이 거의 그대로여서 사용자가 완료 여부를 다시 판단해야 했던 사례가 있었다.

성공 표시만 있는 상태

메시지는 성공인데 값·파일·화면은 이전 상태다.

결과까지 바뀐 상태

새로고침이나 재조회 뒤에도 바뀐 값·파일·화면이 그대로 확인된다.

성공 메시지와 실제 결과를 따로 본다

화면에 성공이라고 떠도 저장 대상이 바뀌지 않았다면 사용자가 원한 결과는 나오지 않은 것이다. 완료된 값과 아직 수정 중인 값을 화면에서 구분할 수 없다면 성공 표시 하나로는 부족하다.

테스트는 성공 메시지가 뜬 다음부터 시작한다. 저장 뒤 새로고침해 바꾼 값이 남는지, 업로드 뒤 실제 파일이 바뀌는지, 계정 변경 뒤 다시 조회해 새 값이 보이는지 확인한다.
