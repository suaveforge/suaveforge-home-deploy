2026년 9월 3일

목록 데이터와 페이지 상태가 어긋나면 빈 화면과 오래된 행이 남는다

삭제나 필터로 결과 수가 줄었는데 페이지 번호나 화면의 행이 이전 상태로 남으면 빈 목록이 보이거나 이미 지운 행이 계속 표시될 수 있다. 데이터가 바뀐 뒤에는 전체 페이지 수를 새 전체 건수와 페이지당 표시 개수로 다시 계산한다. 현재 페이지 번호가 새 범위 안에 있는지 확인하고, 화면에 보이는 행은 새 조회 결과로 바꾼다.

2026년 9월 2일

성공 메시지가 떠도 결과가 바뀌지 않으면 실패다

저장, 업로드, 계정 수정, 로그 다운로드처럼 서로 다른 작업에서도 성공 표시는 떴지만 실제 데이터나 파일은 바뀌지 않은 사례가 반복된다. 완료 여부는 메시지가 아니라 작업 뒤의 상태로 확인해야 한다.

2026년 9월 2일

중간 상태가 남으면 다음 행동까지 막힌다

가입, 취소, 삭제가 끝나지 않은 상태로 남으면 다음 행동도 막힐 수 있다. 실제 사례에서는 앞 단계에서 남은 상태 때문에 다시 가입하거나, 새 수업을 신청하거나, 복원을 시도하는 다음 행동까지 진행하지 못했다.

2026년 9월 2일

삭제 대상과 영향 범위를 헷갈리면 피해가 커진다

비슷한 이름의 항목을 잘못 지우거나, 빈 워크스페이스 대신 주 워크스페이스를 지우거나, 휴대폰에서 지운 사진이 동기화된 사진 계정에서도 사라진 사례가 있다. 공통점은 삭제 전에 대상과 영향 범위를 충분히 구분하기 어려웠다는 것이다.

2026년 9월 2일

같은 배포 실패라도 멈춘 단계는 다르다

실행 환경, 의존성, 권한, 배포 파일 묶음 생성과 검증은 서로 다른 단계다. 겉으로는 모두 배포 실패로 보여도 어디에서 멈췄는지에 따라 원인 후보와 확인 순서가 달라진다.

2026년 9월 1일

실수로 지운 뒤 되돌리지 못하는 일이 반복된다

사진, 문서, 노트, 위키를 실수로 지운 뒤 복구 방법을 찾지 못하거나, 복원해도 원래 상태가 완전히 돌아오지 않은 사례가 서비스마다 반복된다. 삭제 실수를 완전히 막기 어렵기 때문에 복구 경로가 실제로 작동하는지가 중요하다.
